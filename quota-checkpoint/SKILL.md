# 按用户命令监测额度与保存续接

## 命令入口

只执行用户当前直接下达的命令。先辨别直接指令与讨论、举例、引用、修改技能或“不执行”的要求；后者不查询额度、不启动监测、不暂停项目。自动发现已关闭，首次必须显式写 `$quota-checkpoint` 或在宿主界面中选中技能。加载后只处理用户对本项目的直接命令；项目大小、工作时长、昂贵模型或旧检查点均不是授权。只作用于用户指定项目。

| 直接命令示例 | 行为 |
| --- | --- |
| “自动运行监测额度”“开始监测本项目额度”“启用 quota-checkpoint” | 开启本项目监测，取得一次基线，保存授权状态，之后按周期监测 |
| “停止工作”“暂停项目”“停下来保存进度” | 立即停止推进并保存，无论是否开启监测、额度多少；不先查额度 |
| “继续工作”“接着做上次项目”“按检查点恢复” | 核对并恢复原任务；仅在之前明确开启且未关闭监测时恢复监测 |
| “关闭额度监测”“不用再查额度” | 关闭监测，项目工作继续；不误认为停止项目 |
| “检查/修改这个 skill”“比如我说停止工作”“本次不执行” | 只讨论、检查或修改，不执行这些项目动作 |

明确的停止命令不再追问确认；确有歧义且影响是否停止时先澄清。询问状态或重置时间不是继续指令。新聊天尚未加载本技能时，单独一句“停止工作”不能保证加载该技能；可靠写法是 `$quota-checkpoint 停止工作并保存进度`，只保存暂停，不开启监测。加载后同一项目可直接使用自然语言停止/继续命令。

## 原范围与质量

完整保留原始目标、全部交付物、功能、技术深度、必要验证和验收标准。项目或环节很大、时间长、额度低，都不构成缩水、简化方案、少做验证、降低模型或推理强度、用草稿代替成品的理由。

允许在完整保留最终范围与标准的前提下安排阶段和保存点；不为迎合检查周期强制将每个环节压成几分钟，不硬切思路。不能完成的部分明确保留待办，额度不足时保存等待恢复，不宣布提前完成。救急交接可以简短，正文和交付标准不能随之简化。

记录实际可见的模型、推理与速度设置，未知写未知。原设置不可用或确需改范围时由用户选择，不静默降级。

## 仅在开启后的监测

启用时读取一次真实额度。之后按所有适用窗口中最低剩余值确定复查周期：

| 最低剩余额度 | 连续主动工作后的复查周期 |
| --- | --- |
| 高于 50% | 15 分钟 |
| 高于 25%、不超过 50% | 10 分钟 |
| 高于 10%、不超过 25% | 5 分钟 |
| 高于 5%、不超过 10% | 3 分钟 |
| 不超过 5% | 保存并暂停 |

主动工作不含暂停、等待用户、纯下载或外部构建等待；不为计时频繁轮询，也不在每个环节后重复查。高消耗模型不自动将周期缩为每分钟。用户主动要求立即查询、实际发生限额错误或明确改变模型/速度/并发设置时，可在最近可执行边界额外读取一次；普通工具调用和日常上下文增长不是频繁加查的理由。

这是工作边界流程，不是后台定时器。到期在最近可执行边界检查；无法保证中断一次长推理或平台不支持中断的工具调用。收到停止指令后，在能处理指令的第一个边界优先停止推进。

到期才发现并调用只读 `get_usage_limits`。接入或字段不明时读 [额度来源与计算](references/quota-policy.md)。`scripts/assess.py` 只计算已取得的读数，不自行联网。

- 高于 10%：继续完整工作；估算不足时提前保存，不因环节大而降低要求、强制缩短环节或提高暂停门槛。
- 高于 5%、不超过 10%：评估下一完整环节、保存及必要恢复成本，够则继续，不够则保存暂停；不能通过缩水把“不够”变成“够”。
- 不超过 5%：立即保存暂停，不开新环节。
- 服务端限额/额度未知：先保存并如实说明，不伪造可用额度或无限重试。用户停止命令始终优先。

剩余值是 `100 - usedPercent`，分别保护所有适用窗口；读数缺失/过期为未知，到重置时间不证明恢复。整数读数不变时短期沿用可信速率，设置改变或窗口重置后重建基线。仅使用普通额度，不购买、不兑换重置券、不切账户。

完整 JSON 留本地，模型只读必要摘要；参考按需读取，已有要求和决策直接沿用，避免每次重写交接。不启动守护进程、注册自动化或修改其他技能/AGENTS.md。

## 停止并保存：不依赖监测开启

收到明确停止命令后，不先读额度、不跑新测试、不继续处理“顺手完成”的问题。只做保存当前现场所必需且已授权的操作，未完成验证标记“未验证”并留待恢复。

正式保存与恢复读 [检查点与恢复](references/checkpoint.md)。沿用项目进度目录，否则使用 `.codex-progress/<任务唯一标识>/`。不同项目分开；项目归属不清时先保留现场，再定位正确项目。

1. 尽早写救急记录：目标、当前文件、正在做什么、未完成操作、下一步和运行任务。
2. 保存完整交接：全部要求和验收标准、已完成/待办、关键决策及理由、否定方案、原始资料、验证命令与证据、实际产物、模型设置、运行任务及外部副作用。
3. 协调本项目可控制的子代理/模型任务保存并暂停，记录确认与未确认状态；不假设父任务停止就全部停止，不干预其他聊天。不擅自终止可能破坏资料的外部事务；不可中断操作如实记录。
4. 用 `scripts/checkpoint.py` 发布版本化交接和文件指纹并读回核对。另在本任务 `control.json` 保存监测授权和计时状态，格式见参考。未确认的监测授权默认关闭。
5. 回复暂停状态、检查点路径、未保存/未验证项和恢复方法，结束本轮。不后台重试、不定时唤醒、不因额度恢复自动继续。

写入失败如实报告，在回复中给出最小交接，不宣称已落盘。检查点存记录和文件指纹，实际工作文件也须保存。

监测已开启时，先建检查点，之后按实质里程碑轻量更新，完整检查点通常每约 15 分钟主动工作更新。保存周期与额度查询分开，保存不附带查询。未开启监测时不因项目规模建立后台保存循环，但用户停止命令仍须保存。

## 继续工作

1. 读取本任务最新交接、`control.json` 及用户最新要求。无明确监测授权或旧记录没有该状态时默认关闭；继续本身不授权开启监测。
2. 此前明确开启且未关闭监测时，重读额度建立基线，按 5%–10% 规则判断；监测关闭时直接核对现场恢复，不自行查询。
3. 核验文件、分支/提交及用户暂停期间的改动，重读下一环节相关原始资料和决策，核对外部操作是否已执行、进程是否仍在运行，避免重复副作用。
4. 恢复原模型设置与完整计划，完成必要验证，从准确断点继续。停止时未做的验证仍须补齐；不覆盖用户的新工作，不降低标准。

保存可核对的结论与依据，不保存隐藏思维链，也不能保证跨会话质量数学上完全一致。通过保留全部要求、真实产物、关键决策、未决问题和验证证据，尽可能维持续接质量。

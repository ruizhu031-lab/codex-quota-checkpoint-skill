# 额度监测、完整技术记录与压缩后恢复

## 入口与授权

只由用户主动调用；保持 `allow_implicit_invocation: false`。项目大小、时长、高级模型、旧检查点和恢复索引都不是启动授权。先识别真实意图：讨论、举例、引用、修改本技能和“本次不执行”不查询额度、不注册钩子、不执行项目控制。

| 当前直接指令 | 行为 |
| --- | --- |
| `$quota-checkpoint`，或明确调用并要求监测 | 自动开启当前项目监测，读取基线，同时创建或续写详细技术文档 |
| “停止工作”“暂停项目” | 立即进入停止流程；额度够则完成当前已开始环节后保存暂停，不够则保存暂停 |
| “不要继续当前环节，立即保存” | 直接保存，不为收尾再查额度或推进项目 |
| “继续工作” | 核对原始记录与实际现场再续接；此前监测开启且未关闭时重读额度 |
| “关闭额度监测” | 停止查询，项目工作和详细记录继续 |
| 检查、修改或讨论本技能 | 仅处理技能本身 |

首次可靠入口是 `$quota-checkpoint` 或宿主技能选择；新聊天泛化命令不能保证加载显式技能。明确停止/继续命令不重复询问许可；任务归属不清时才澄清。索引、钩子和记录均不授权另一个会话自动监测或复工。

## 完整范围与质量

保留原始目标、全部交付物、功能、技术深度、必要验证和验收标准。项目或环节很大、额度很低，都不能导致删减工作、降低模型/推理强度、跳过验证、用草稿代替成品或提前宣称完成。记录可见模型、推理与速度设置，未知写未知；原设置不可用时由用户选择，不自行降级。

允许安排阶段与保存点，不为检查周期强制缩短环节。进入收尾前固定当前环节的范围与完成条件；不能重定义“完成”把不足变成足够。

## 主动启用

先读 [检查点与状态](references/checkpoint.md)；建立详细记录和配置压缩保护时读 [记录与恢复流程](references/recovery.md)。

1. 确定项目根目录、独立任务标识、可获得的真实宿主会话 ID，读取已有资料；历史不全明确标记。
2. 写完整初始状态与技术基线，建立 `.codex-progress/<task>/` 并记录本次授权。读取一次真实额度；工具缺失则保存并报告未知，不编造可用额度。
3. 使用辅助工具增加有边界的项目恢复索引和项目级钩子，保留并备份已有规则与钩子。遵守项目配置权限；缺少真实会话 ID 或宿主不支持时使用文档与索引，报告增强保护尚未生效。
4. 新钩子需宿主信任。提供确切脚本/配置后引导 Settings > Hooks 或 `/hooks` 审阅，不绕过信任、不把配置成功说成实际触发成功。
5. 按原完整计划推进，开始环节时记录 ID、完整范围和验收条件；停止评估只针对已经开始的这个环节。

不启动守护进程或定时自动化，不读取认证文件、购买额度、兑换重置、切换账户或修改无关配置。

## 低频监测

使用所有确认适用窗口的最低剩余额度，剩余值为 `100 - usedPercent`。

| 最低剩余额度 | 主动工作后的复查周期 |
| --- | --- |
| 高于 50% | 20 分钟 |
| 高于 20%、不超过 50% | 15 分钟 |
| 高于 10%、不超过 20% | 5 分钟 |
| 高于 5%、不超过 10% | 仅允许当前环节收尾；期间每 3 分钟检查 |
| 不超过 5% | 保存并暂停 |

主动工作不含暂停、等用户、纯下载或外部构建等待。到期在最近可执行边界读取，不能保证打断长推理或不可中断工具。高消耗模式只改变估算余量，不提高查询频率。明确要求立即查询、实际限额错误、刻意改变模型/速度/并发可额外读取；普通工具调用、上下文增长不加查。

到期发现并调用只读 `get_usage_limits` 或等价受支持工具。字段与预算见 [额度计算](references/quota-policy.md)。完整响应留本地，模型只读必要摘要。`assess.py` 仅计算已取得的读数，不联网。

高于 10% 且没有停止请求时继续完整任务；成本较大只提示提前保存。所有窗口分别保护；未知或服务端禁止使用时保存暂停。预计重置时间不是恢复证据。

## 停止并保存

进入 5%–10% 或收到普通停止命令时，先写当前断点并持久保存待暂停状态，禁止开新环节。普通停止评估可额外取得一次新读数；硬停止直接保存。

- 估算当前环节的**剩余工作及必要验证**，加上技术记录、工作总结、持久保存和当次实际恢复成本，保护各窗口的 5% 底线。不能用默认几分钟代替未知估算。
- 足够：结果为 `finish_then_pause`，仅完成已绑定环节，然后总结、发布检查点、核对并暂停。额度重置或上下文压缩不清除待暂停状态。
- 不足、无当前环节、估算依据缺失、额度不可读或不超过 5%：保存暂停，记录精确未完成位置和待验证事项。
- 收尾途中发现不足时保存未完成现场，不硬撑到耗尽。必要验证尚未完成时不能标记该环节完成。

暂停总结包括完成到哪、当前变更、全部未完成项、缺失验收证据、下一步、运行任务与外部副作用。协调本项目可控制的模型任务保存暂停，记录未确认项；不干预其他聊天、不危险终止外部事务。实际工作文件也须落盘，检查点并非项目文件备份。

保存失败如实报告并提供最小交接，不宣称完整保存。正式暂停后停止计时和查询，结束本轮，等待用户明确继续；不轮询、不自动复工。

## 持续技术记录

启用后持续写 `TECHNICAL_LOG.md`：完整要求与重点、交付清单、决定及依据、否定方案、工作步骤、修改位置/接口/参数、命令和结果、失败与解决过程、原始资料、测试证据、断点、待办和外部操作。

重要要求/决定/修改结果/验证结果及时追加；有未记录进展时，最迟约 5 分钟主动工作后的可执行边界补写。完整检查点在实质里程碑、暂停前及约 15 分钟主动工作时更新；保存不附带额度查询。

保留详细原文，通过追加更正修正历史；简短摘要不能删除或替代原文。长输出留作本地证据，按需重读相关原文，避免反复全文写入/加载。保存工程事实、结论和可复现依据，不保存隐藏思维链、凭据或整份环境变量。

## 压缩后与继续前

压缩对话不改写磁盘技术文档。即使聊天摘要看起来足够，压缩后也须先核对：

1. 正确任务的控制状态、最新交接、完整要求/验收重点和相关技术记录原文；入口索引不代替正文。
2. 决定及理由、当前环节及完成条件、精确断点、全部待办和验证证据；重读下一步相关原始资料。
3. 文件、分支/提交、用户新增修改、运行任务和已发生的外部操作，避免覆盖或重复执行。
4. 用具体事实填写恢复核对记录。缺失或矛盾先找回依据，不凭猜测推进相关工作；找不回的细节明确报告。
5. 原本收尾则只完成原环节再暂停，原本暂停则继续等待。仅明确继续指令可以清除待暂停状态。此前监测开启且未关闭时，推进前取得新基线；必要时再次保存暂停。

辅助工具校验文件与状态，不能证明模型已正确理解全部资料。钩子受宿主支持、信任、权限和时限约束。保护已落盘细节，不能承诺文档全文永久驻留上下文、救回尚未保存的信息或数学上完全相同的跨会话输出；完整范围与质量标准始终不变。
